# SmartBite AI modules: technical notes

The simple overview is in `README.md`; how to connect the models to the backend is in `INTEGRATION.md`.
This page is for training, evaluating and reproducing the models.

Server-side food photo recognition for SmartBite's human-in-the-loop logging flow (spec 3.1.5, FR-SCAN-01..07).
A photo goes in. Out come the **top-3 calibrated dish suggestions**, a **confidence band** for the verification
screen, **grams estimated from the photo**, and **nutrients**. Nothing is ever logged automatically
(`autoLogged: false`).

> Not medical advice. Nutrient values are estimates from food-composition databases; grams are estimated from the
> photo and must be confirmed or edited by the user.

## Pieces

| Piece | Where |
|---|---|
| Leakage-safe dataset build (dedupe, splits) | `smartbite_cv/prepare.py`, `configs/data*.yaml`, `configs/classes*.yaml` |
| Two-stage fine-tuning (timm, ImageNet weights) | `smartbite_cv/train.py`, `configs/train/*.yaml` |
| Evaluation, calibration, confidence bands | `smartbite_cv/evaluate.py`, `metrics.py`, `bands.py` |
| Integrity audit (overfitting, leakage, robustness) | `smartbite_cv/audit.py` |
| Portion model (fixed overhead camera) | `smartbite_cv/portion.py` |
| Plate detection and plate-relative portion model | `smartbite_cv/plate.py`, `plate_portion.py`, `plate_bench.py` |
| ONNX export and inference | `smartbite_cv/export.py`, `predict.py`, `model_files.py` |
| Nutrition lookup (swappable provider) | `smartbite_cv/nutrition.py`, `nutrition/nutrition_v2.csv` |
| Example backend | `examples/fastapi_server.py` |
| Kaggle/Colab notebooks | `notebooks/` (generated by `tools/build_kaggle.py`) |
| Reports | `reports/` |

## Models and where they live

Training and export write to `artifacts/<name>/` (local, not in git: `model.onnx`, `model_meta.json` or
`portion_meta.json`, `bands.yaml`). `python tools/publish_models.py` copies the ones the app uses into `models/`
with plain names (`food_name_finder.onnx` + `_settings.json` + `_how_sure.yaml`, and so on). Every loader accepts
either form: a named `.onnx` file in `models/`, or an export folder.

| `models/` name | Export folder | What it is |
|---|---|---|
| `food_name_finder` | `artifacts/efficientnet_b0_v2` | EfficientNet-B0, 76 classes (75 foods + `not_food`) |
| `food_name_finder_small` | `artifacts/mobilenetv2_v2` | MobileNetV2 baseline (not used by the app) |
| `food_weight_finder_with_plate` | `artifacts/plate_portion` | Plate-relative portion model (input: plate-only view) |
| `food_weight_finder_no_plate` | `artifacts/portion` | Portion model trained on the fixed overhead camera |

## Results

v2 (`configs/*_v2.yaml`) adds the Pakistani SmartFoodAnalyzer dataset and Khana: 76 classes, 28,556 deduplicated
photos, a portion model trained on Nutrition5k, and a 79-food nutrition table (`nutrition/nutrition_v2.csv`).

| Dish classifier (EfficientNet-B0) | top-1 / top-3 |
|---|---|
| Internal test | 82.6% / 92.9% |
| Real-world (Wikipedia photos) | 56.9% / 74.4% |

Grams, on weighed Nutrition5k test dishes:

| Photo | Fixed-camera portion model | Plate model |
|---|---|---|
| Overhead (training camera) | 27 g (14%) | 28 g (14%) |
| Camera farther (0.6x) | 101 g (51%) | 29 g (15%) |
| Side angle, other camera, all stills | 139 g (70%) | 55 g (27%) |
| Side angle, plate mostly in frame | 107 g (56%) | 41 g (22%) |

Full results, the integrity audit and limitations: `reports/v2_results.md` and `reports/plate_results.md`.

## Inference

```powershell
py -3.12 -m venv .venv; .venv\Scripts\activate
pip install -r requirements.txt
python -m smartbite_cv.predict path\to\meal.jpg                         # dish + grams + nutrients (models/ by default)
python -m smartbite_cv.predict path\to\meal.jpg --no-plate              # skip the plate detector
python -m smartbite_cv.predict path\to\meal.jpg --grams 250             # nutrients for 250 g of the top guess
python -m smartbite_cv.predict path\to\meal.jpg --grams 250 --label daal --json   # user picked another dish
```

Confidence bands (thresholds in `models/food_name_finder_how_sure.yaml`, chosen on the validation split):

| band | app behaviour |
|---|---|
| `high` | top guess pre-selected; user must still confirm |
| `medium` | "Is it one of these?" with the top 3 |
| `low` | "Couldn't recognise it, search manually", top 3 shown as hints (also when the best guess is `not_food`) |

## Reproduce everything

```powershell
# 0. data (about 12 GB in data/raw). Kaggle CLI needs a Kaggle API token
kaggle datasets download -d iamsouravbanerjee/indian-food-images-dataset -p data/raw/iamsouravbanerjee_indian-food-images-dataset --unzip
kaggle datasets download -d anshulmehtakaggl/themassiveindianfooddataset -p data/raw/anshulmehtakaggl_themassiveindianfooddataset --unzip
kaggle datasets download -d useractivated/dataset -p data/raw/useractivated_dataset --unzip
kaggle datasets download -d l33tc0d3r/indian-food-classification -p data/raw/l33tc0d3r_indian-food-classification --unzip
kaggle datasets download -d cdart99/food20dataset -p data/raw/cdart99_food20dataset --unzip
kaggle datasets download -d utkarshsaxenadn/fast-food-classification-dataset -p data/raw/utkarshsaxenadn__fast-food-classification-dataset --unzip
kaggle datasets download -d trolukovich/food5k-image-dataset -p data/raw/trolukovich__food5k --unzip
# Food-101: Hugging Face parquet mirror (same bytes as the official tarball / kmader/food41)
#   download data/*.parquet from https://huggingface.co/datasets/ethz/food101 into data/raw/hf_food101, then:
python tools/extract_food101_parquet.py --src data/raw/hf_food101 --out data/raw/food101 --classes samosa chicken_curry pizza hamburger french_fries fried_rice omelette chicken_wings club_sandwich hot_dog donuts ice_cream chocolate_cake spaghetti_bolognese spaghetti_carbonara greek_salad caesar_salad
# v2 adds SMF and Khana (sources and licences in reports/v2_results.md)

# 1. manifest (dedupe + split) and resized cache
python -m smartbite_cv.prepare --config configs/data_v2.yaml --classes configs/classes_v2.yaml --cache

# 2. tests
python -m pytest -q

# 3. GPU training on Kaggle (private notebooks; Colab works too, see the notebook's first cell)
python tools/build_kaggle.py --user <kaggle-username> --version v2       # dish classifiers
python tools/build_kaggle.py --user <kaggle-username> --version portion  # fixed-camera portion model
python tools/build_kaggle.py --user <kaggle-username> --version plate    # plate benchmark + plate model (2 GPUs)
kaggle datasets create -p kaggle_out/bundle_v2/code          # later: kaggle datasets version -p ... -m "msg"
kaggle kernels push -p kaggle_out/bundle_v2/kernel
kaggle kernels output <kaggle-username>/smartbite-food-train-v2 -p kaggle_out/results_v2

# 4. on a GPU machine the same steps run directly, for example:
python -m smartbite_cv.train --config configs/train/base.yaml --config configs/train/efficientnet_b0.yaml --config configs/train/v2.yaml
python -m smartbite_cv.evaluate --run runs/efficientnet_b0
python -m smartbite_cv.export --run runs/efficientnet_b0 --out artifacts/efficientnet_b0_v2
python -m smartbite_cv.audit --run runs/efficientnet_b0_v2 --compare runs/mobilenetv2_v2

# 5. copy the exported models into models/ for the app
python tools/publish_models.py

# 6. nutrition table (sources in nutrition/README.md)
python tools/build_nutrition.py
```

## Swapping the nutrition source

`smartbite_cv.nutrition` exposes `NutritionProvider.get(label) -> NutritionInfo | None`. A Firestore-backed provider
(`foods` collection) can be passed as `FoodRecognizer(..., nutrition=provider)`. Nothing else changes.

## Known limits

* One dominant dish per photo. Mixed plates return the main dish and one total weight.
* Grams from the photo are estimates; the user confirms or edits them. The grams models were trained and tested on
  Nutrition5k cafeteria dishes; no Pakistani dish has been weighed yet.
* The dish classifier was trained and tested on web images, which overstates real-world accuracy.
* Dataset images come from third parties; some datasets are academic or non-commercial only. Keep the repo private.
