# SmartBite: food recognition and calorie estimation (Phase 1)

Server-side food photo recognition for SmartBite's human-in-the-loop logging flow (spec 3.1.5,
FR-SCAN-01..07). A photo goes in. Out come the **top-3 calibrated dish suggestions** and a **confidence
band** for the verification screen, plus **calories for the portion the user chooses**.
Nothing is ever logged automatically (`autoLogged: false`); the Phase 2 API will enforce that.

> Not medical advice. Calorie values are estimates from food-composition databases; portion size
> comes from the user, not from the photo.

## What is in Phase 1

| Piece | Where |
|---|---|
| Leakage-safe dataset build (dedupe, splits) | `smartbite_cv/prepare.py`, `configs/data.yaml`, `configs/classes.yaml` |
| Two-stage fine-tuning (timm, ImageNet weights) | `smartbite_cv/train.py`, `configs/train/*.yaml` |
| Evaluation, calibration, confidence bands | `smartbite_cv/evaluate.py`, `metrics.py`, `bands.py` |
| ONNX export and inference (no PyTorch needed) | `smartbite_cv/export.py`, `predict.py` |
| Nutrition lookup (swappable provider) | `smartbite_cv/nutrition.py`, `nutrition/nutrition.csv` |
| Real-phone-photo evaluation | `smartbite_cv/eval_folder.py`, `eval_phone_photos/` |
| Kaggle/Colab notebook | `notebooks/smartbite_food_train.ipynb` (generated by `tools/build_kaggle.py`) |
| Report notes | `reports/` |

Models: **EfficientNet-B0** (primary) and **MobileNetV2** (baseline named in the original spec), one
dish per photo, 32 classes (31 foods + `not_food`). Results: `reports/phase1_report.md`.

## Quick start (inference)

```powershell
py -3.12 -m venv .venv; .venv\Scripts\activate
pip install -r requirements.txt
python -m smartbite_cv.predict path\to\meal.jpg                         # top-3 + default serving
python -m smartbite_cv.predict path\to\meal.jpg --grams 250             # calories for 250 g of the top guess
python -m smartbite_cv.predict path\to\meal.jpg --grams 250 --label daal --json   # user picked another dish
```

```python
from smartbite_cv.predict import FoodRecognizer
from smartbite_cv.nutrition import calories

rec = FoodRecognizer("artifacts/efficientnet_b0")
result = rec.predict("meal.jpg")          # {"band", "message", "suggestions": [...3], "autoLogged": False, ...}
kcal = calories("biryani", 250)           # kcal per 100 g x grams / 100
```

Bands (thresholds in `artifacts/<model>/bands.yaml`, chosen on the validation split):

| band | app behaviour |
|---|---|
| `high` | top guess pre-selected; user must still confirm |
| `medium` | "Is it one of these?" with the top 3 |
| `low` | "Couldn't recognise it, search manually", top 3 shown as hints (also when the best guess is `not_food`) |

## Swapping the nutrition source (Phase 2)

`smartbite_cv.nutrition` exposes `NutritionProvider.get(label) -> NutritionInfo | None`. Phase 2
implements a Firestore-backed provider (`foods` collection) and passes it to `FoodRecognizer(...,
nutrition=provider)` / `calories(label, grams, provider)`. Nothing else changes.

## Known limits (details in the report)

* One dominant dish per photo. Mixed plates return the main dish; the app adds the rest via search.
* No portion estimation from the image; grams come from the Portion Selector.
* Trained and tested on web images only, which overstates real-world accuracy. Use `eval_phone_photos/`.
* Several Pakistani staples have no usable public data (nihari, karahi-specific photos, plain rice,
  eggs, fruit, shawarma) and are not in the model; they fall back to manual search.
* Dataset images are scraped from the web by third parties; academic, non-commercial use only.
